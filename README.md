# Telegram-бот и приложение «Клиника»

Подготовлена основа общего рейтинга. **Правила рейтинга пока не выбраны, баллы не начисляются, автоматическая рассылка выключена.**

## Что подготовлено

- В приложении есть вкладка «Рейтинг» с состоянием «правила пока не настроены».
- Смены, экзамены и блоки подключены к отправке событий об ответах на встроенные вопросы: выбранный ответ, правильность, время получения. Свои вопросы остаются локальными.
- Сервер проверяет подпись Telegram `initData`, срок сессии и выбранный ответ по встроенному банку. Telegram ID берётся из проверенной подписи.
- В базе `game_events` хранятся события. Повторная отправка одного события не создаёт копию. Переданные клиентом баллы сервер игнорирует.
- Для будущего рейтинга готовы получение лидеров и личного места, формирование топ-3, очередь персональных рассылок, команды `/top`, `/stop`, `/subscribe`.
- Незавершённая рассылка сохраняется в SQLite. После обычного перезапуска продолжается с неотправленных сообщений. Блокировка бота отключает дальнейшую рассылку пользователю.
- Викторина в сообщениях бота удалена. `/start` показывает приветствие и кнопку приложения. Команды `/question` и `/me` больше не используются; старые кнопки вопросов предлагают открыть приложение. Существующие пользователи и данные базы сохранены.

## Запуск на компьютере

Нужен Python 3.10 или новее. В папке проекта:

```powershell
python -m pip install -r requirements.txt
python bot.py
```

В локальном `.env` уже сохранён прежний токен бота. На другой машине создайте `.env` по образцу `.env.example` и укажите `BOT_TOKEN`. Переменные окружения имеют приоритет над `.env`.

Бот запускает локальный API по адресу `http://127.0.0.1:8080`. Он работает, пока запущен процесс Python. Не запускайте одновременно две копии бота с одним токеном.

Пока `window.RATING_API_URL` в `rating-config.js` пустой, приложение на GitHub Pages работает с прежним сохранением прогресса, а подключение общего рейтинга отключено. Локальный API на компьютере недоступен другим игрокам по этому адресу.

## Подключение API позже

1. Разместите бот и API на сервере с постоянным диском либо предоставьте компьютеру стабильный публичный HTTPS-адрес. GitHub Pages обслуживает HTML/JS; Python запускается отдельно.
2. Сохраните `bot.db` на постоянном диске и делайте резервные копии. `DB_FILE` может содержать абсолютный путь. Для размещения за обратным прокси оставьте `API_HOST=127.0.0.1`; если хостинг требует прослушивать внешний интерфейс, используйте `API_HOST=0.0.0.0`. Порт берётся из `PORT`.
3. В `rating-config.js` укажите публичный HTTPS-адрес API, например `https://api.example.ru`.
4. В настройках сервера задайте `ALLOWED_ORIGIN=https://maxmaximovv192-collab.github.io` — без пути `/my-game/` и завершающего слеша.
5. Опубликуйте вместе `index.html`, `rating-config.js`, `rating.js`. Откройте приложение через `/play`. Ответы начнут попадать в `game_events` с нулём баллов.

Не публикуйте `.env` или `bot.db`. Они исключены через `.gitignore`; загрузка файлов в GitHub должна использовать явный список файлов проекта. Токен не передаётся в HTML или JavaScript.

## Где появятся правила

Файл `rating_rules.py` содержит `RULES_READY=False` и функцию `points_for_answer`, которая пока возвращает `0`. После согласования формулы здесь можно добавить начисление баллов. Агрегация и правила равенства мест находятся в `RatingStore._ranking` и `_places` в `leaderboard.py`; сейчас подготовлен общий рейтинг по сумме баллов с одинаковым местом при равных результатах.

До включения нужно согласовать: за что начислять баллы, за какой период сравнивать игроков, как учитывать повторные прохождения, экзамены, скорость, ошибки и равные результаты. Уже записанные события не пересчитываются автоматически: возможность пересчёта нужно добавить под выбранные правила.

Данные об ответах приходят из браузера. Проверка подписи подтверждает личность, а проверка ответа — соответствие банку; это ещё не защита от автоматической отправки известных ответов. Для соревновательного рейтинга стоит добавить выдаваемые сервером игровые попытки и ограничения согласно будущим правилам.

Рассылка включится только когда `RULES_READY=True` **и** `DAILY_REPORTS_ENABLED=true`. `DAILY_TIME=21:00` в примере — изменяемая заготовка, время указано по Москве. Текущая заготовка фиксирует общий рейтинг в момент рассылки; отдельный дневной рейтинг пока не выбран и не реализован. После включения бот отправляет сообщения только пользователям своей базы, которым доступна личная переписка с ботом. `/stop` отменяет ожидающие сообщения, `/subscribe` включает следующие рассылки.

Если сервер выключен в назначенное время, при запуске позже в тот же день очередь будет создана по текущему состоянию. Пропущенные дни автоматически не восстанавливаются. В редком случае остановки между отправкой сообщения в Telegram и записью статуса в SQLite возможна повторная доставка.

## Проверки

```powershell
python -m unittest discover -s tests -v
node tests/test_frontend.cjs
```

Тесты используют временные базы и подмену Telegram, не отправляют сообщения реальным пользователям. Проверяются авторизация, миграция старой базы, запись и повторная доставка событий, отсутствие баллов без правил, личные места, отключение рассылки и её возобновление. Проверки также запускаются в GitHub Actions.

Проверка подписи реализована по [официальной документации Telegram Mini Apps](https://core.telegram.org/bots/webapps#validating-data-received-via-the-mini-app).
